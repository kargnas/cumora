The fork's own web UI (`src/next`) follows the `web-design` skill: read `.agents/skills/web-design/SKILL.md` before you build, change or review it. Upstream's classic UI is outside its scope: a change there keeps the classic style, so upstream merges stay small.

Every rule in the skill applies to `src/next` unless an AGENTS.md, such as `src/next/AGENTS.md`, or this file has a rule on the same point; then that rule wins. This file changes the skill in these points:

- `src/next` is plain CSS with `nx-` classes, not shadcn or Tailwind. Skip the skill's Stack section, and map its Tailwind classes onto the same-named tokens in `src/next/styles/tokens.css`. That file decides which tokens exist and what they hold, even where the skill or the transitions guide lists other values (its `--ease-in-out` is a different curve) or more tokens.
- The bundled transitions guide is a reference, not code to paste. Rebuild a recipe with the motion tokens, classes and smoothness rules of `src/next`, and build menus and dialogs on `Menu` and `Dialog` from `src/next/ui/primitives.tsx`.
- Do not carry the recipes' bugs into a rebuild. A closed or inactive state hidden only by `opacity` and `pointer-events` (menus, dialogs, panels, side-by-side pages) stays reachable by Tab and screen readers, so make it `inert` or unmount it. Dark mode is the `dark` class on `<html>`, not `data-theme`. Recipe 13's `cubic-bezier()` parser rejects the spaced values the recipe uses, and its reduced-motion guard does not stop its `requestAnimationFrame` loop. Recipe 32 writes `innerHTML`, so it must never receive chat or agent text.
- Wherever the skill fetches the Vercel guidelines, fetch `command.md` at commit [`434b7f9`](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/434b7f91364665f2f733b310ec54809bf8f37937/command.md) instead of `main`. If it cannot be fetched, say so in the review and continue with the skill's rules; the review stays valid.
